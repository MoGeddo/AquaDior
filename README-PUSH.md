# إشعارات الهاتف الخارجية (Push)

التطبيق يحتفظ بإشعاراته داخل قاعدة البيانات كما هي، ويمكن بعد ضبط الحسابات إرسال تنبيه عام إلى إشعارات نظام الهاتف عبر **OneSignal** عند إنشاء إشعار داخلي. التكامل مهيأ لتطبيق Capacitor على Android/iOS، ونسخة الويب المدعومة عبر OneSignal Web Push. لا نرسل تفاصيل الرصيد أو الخصومات أو أسماء الأشخاص إلى شاشة القفل؛ نص التنبيه عام فقط.

`.github/workflows/build-ios-simulator.yml` يبني نسخة iOS Simulator غير موقعة يدويًا لفحص التوافق فقط؛ ليست IPA ولا يمكن تثبيتها على iPhone أو رفعها إلى TestFlight. رفع TestFlight يحتاج عضوية Apple Developer وتوقيعًا وبيانات App Store Connect.

## ما الذي أُضيف؟

- زر اشتراك اختياري لكل جهاز في مركز إشعارات العامل وإعدادات الإدارة. لا تظهر نافذة إذن النظام إلا بعد ضغط المستخدم.
- إسناد جهاز المستخدم إلى حسابه عبر معرّف Supabase الداخلي. عند تسجيل الخروج، يُفصل الجهاز عن الحساب الحالي.
- طابور خادمي إضافي يُنشأ تلقائيًا لكل صف جديد في `public.notifications`، مع محاولات إعادة للإخفاقات المؤقتة.
- Edge Function `push-dispatch` ترسل عبر OneSignal، وتستخدم محتوى عامًا لحماية التفاصيل على شاشة القفل.
- Web Push يستخدم نطاق Service Worker منفصلًا `/onesignal/` حتى لا يتعارض مع Service Worker الخاص بالـPWA.

## متطلبات التفعيل — ليست مُعدّة تلقائيًا

يلزم إنشاء تطبيق OneSignal وضبط بيانات المنصات من حساب الشركة. **لا يمكن إرسال Push فعلي قبل هذه الخطوات**، ولم نربط أو نعدّل مشروع Supabase البعيد من المستودع.

1. أنشئ تطبيقًا في OneSignal واضبط قنوات Web Push وAndroid وiOS التي ستُستخدم:
   - Android: بيانات Firebase/FCM المطلوبة داخل لوحة OneSignal.
   - iOS: مفتاح APNs ومعلومات فريق Apple داخل لوحة OneSignal، مع Bundle ID الحالي `com.mogeddo.workers`. سيُبنى تطبيق iOS لاحقًا عبر Capacitor/Xcode/TestFlight.
   - Web: أضف أصل موقع AquaDior الصحيح في إعدادات Web Push. وعلى iPhone في الويب يلزم iOS 16.4 فأحدث وتثبيت الـPWA على الشاشة الرئيسية؛ نسخة TestFlight تستخدم قناة iOS الأصلية.
2. ضع **OneSignal App ID العام فقط** في `VITE_ONESIGNAL_APP_ID` محليًا، وفي GitHub Actions Repository Variables، وفي Cloudflare Pages Environment Variables لكل من Production/Preview بالاسم نفسه، ثم أعد البناء. هذا المعرّف ليس سرًا.
3. خزّن المفتاح الخاص في Supabase Edge Functions فقط، ولا تضعه في متغيرات `VITE_` أو في Git:

   ```sh
   supabase secrets set ONESIGNAL_APP_ID='APP-ID' ONESIGNAL_REST_API_KEY='REST-API-KEY' PUSH_DISPATCH_SECRET='RANDOM-SECRET'
   supabase functions deploy push-dispatch
   ```

   ولّد `RANDOM-SECRET` عشوائيًا، واستخدم القيمة نفسها لاحقًا في Vault. لا ترسل المفاتيح في المحادثة.
4. راجع `supabase/PUSH-NOTIFICATIONS.sql` وخذ نسخة احتياطية، ثم اختبره أولًا على **مشروع Staging** مطابق للمخطط. هو إضافة لجدول outbox ومشغّل على `notifications` ودالتي claim/complete؛ لم يُنفّذ على أي قاعدة بعيدة.
5. فعّل `pg_cron` و`pg_net` وSupabase Vault للمشروع، واحفظ رابط Edge Function والسر في Vault. راجع `supabase/PUSH-CRON-SETUP.example.sql`؛ لا تشغّله قبل استبدال القيم في محرر Supabase نفسه، ولا تحفظ أسرارًا في المستودع. المجدول يستدعي المرسل كل دقيقة.
6. أعد بناء التطبيق بعد إضافة App ID إلى متغيرات بيئة البناء. على كل هاتف: سجّل الدخول، افتح «الإشعارات»، واضغط «تفعيل إشعارات الهاتف»، ثم وافق على إذن نظام التشغيل.

## اختبار القبول

- جرّب على Staging بحساب عامل وحساب إدارة وجهازين، مع التطبيق في الخلفية ثم مغلقًا.
- أنشئ حدثًا يولّد إشعارًا داخليًا (مثل تعيين مشروع)، وتحقق من وصول التنبيه للجهاز/الأجهزة التي وافق أصحابها على الاشتراك.
- اختبر منع وصول إشعارات حساب سابق بعد تسجيل الخروج ثم دخول حساب آخر على الهاتف نفسه.
- اختبر إيقاف الإشعارات من داخل التطبيق، ثم حذف إذنها من إعدادات iOS/Android.
- ملاحظة: الطابور يُرسل خلال دورة المجدول (حتى نحو دقيقة)، وتُعاد المحاولة حتى 5 مرات. إذا لم يشترك المستخدم في OneSignal فلن يستلم Push، لكن الإشعار يظل محفوظًا داخل التطبيق.

## الخصوصية والأمان

- OneSignal يستقبل معرّفًا داخليًا لحساب المستخدم كي تُوجّه التنبيهات إلى أجهزته. لا نرسل تفاصيل الرصيد/الموقع في Push؛ يتلقى الهاتف نصًا عامًا فقط.
- مفتاح OneSignal REST وسر المرسل يبقيان على الخادم. لا تضع Service Role Key أو مفاتيح APNs/FCM أو REST Key داخل التطبيق، أو Git، أو `VITE_`.
- موافقة إذن النظام اختيارية لكل جهاز؛ رفضها لا يمنع استخدام الإشعارات داخل التطبيق.
